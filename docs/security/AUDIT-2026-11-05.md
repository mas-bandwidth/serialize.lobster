## Findings

### sra-lobster-1: overflowing initialization count

- **Base location:** `src/serialize_stream.lobster:195`.
- **Effect:** A caller-controlled byte count in the top eight positive int64
  values wraps `bytes + 8` negative, bypassing the slack check even for an
  empty string. The constructor returns an unfailed stream with negative
  `num_bits`; a degenerate ranged read can succeed. This violates U7/U16 and
  the constructor's refusal contract. Ordinary wire bytes with a correct
  caller byte count do not trigger it; no out-of-bounds wire read was found.
- **Severity:** low; caller-declaration boundary, inconsistent refusal/state.
- **Reduction:** compare the count against `length(data) - 8` and the maximum
  representable byte-to-bit count before multiplication. Refuse immediately
  as value_out_of_range over zero bits.
- **Status:** open, pin and model being prepared.
- **Pin:** existing `test/uniform/uniform_test.lobster`; initialization seeds
  in the existing fuzz driver; reduced-width TLA+ initialization/latch model
  under `test/uniform/`, including the reversed old-bound witness.

### sra-lobster-2: exported UTF-8 helper trusts its scan count

- **Base location:** `src/serialize_bytes.lobster:19`.
- **Effect:** A direct caller supplying a scan count beyond the string length
  can reach a VM bounds trap, while a negative count returns true without
  checking any bytes. The packet string reader passes the exact allocated
  payload length and does not expose this condition to wire bytes alone.
- **Severity:** low; public helper caller-input boundary, no wire-only trigger.
- **Reduction:** refuse negative or over-capacity scan counts before the first
  byte access. Keep strict UTF-8 validation unchanged for valid spans.
- **Status:** open; direct-helper contract and pin under review.
- **Pin:** proposed extension of `test/strings/strings_test.lobster` and the
  existing fuzz driver, with malformed scan counts as regression seeds.

## Failure and resource behavior

Failed primitive reads return their supplied destination unchanged. A
composite operation may consume its length, flags or alignment before refusing;
the cursor is not rolled back. Later reads consult the terminal latch, keep the
first reason, return their supplied value and consume nothing, including
degenerate ranges and empty/aligned operations. A refused object may contain
fields assigned by earlier successful reads; callers must discard it after
failure. The runtime does not promise transactional object rollback.

String allocation is at most the length already verified to fit the packet,
and at most INT32_MAX, plus the caller-selected packet copy if the padded
constructor is used. There is no allocation from an unchecked wire length,
and UTF-8 work is linear in payload bytes. Packet-size limits and callback
recursion limits remain caller responsibilities. Integer, fixed and float
primitives allocate no input-sized containers and have bounded group counts.

Raw floats reject every NaN/infinity pattern; negative zero and subnormals
retain exact bits. Compressed decode is checked for finiteness after the
specified float32 roundings. Its allowed interval is `[min, min + delta]`,
which may exceed the declared max after float32 rounding; no clamping or new
refusal was added. Writer paths were inspected only where they establish the
wire encoding relied on by the reader.

## Validation

The unchanged base passed `make -j4 test LOBSTER=/usr/local/bin/lobster` through
the Linux bench slot, under `nice -n 10 timeout 600`: `ok 7 test directories`,
zero compiler warnings. Further regression, final gate, bounded fuzz and TLC
results are pending. No profiling or timing work was performed.
